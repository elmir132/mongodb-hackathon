## Existing project decisions retained

The canonical docs already require one shared view for a 60-second first round and a five-minute finalist presentation; the complete correction → scoped precedent/policy update → reuse loop; and the existing ownership: Elmir owns resolution, Sahil owns storage/transport and hosts retrieval, Danny owns core retrieval and orchestration, and Maxime owns the frontend. Preserve prior facts and policies, distinguish retrieved candidates from evidence actually used, and verify persistence and scope. The interface direction does not reassign those responsibilities.

## Implementation choices, not additional user decisions

React/Vite, browser-local memory, CSS perspective and shared 3D wire segments, a temporary local rule adapter, `.txt`/`.md` attachments up to 100 KB, and a labeled example memo are current implementation choices. The sample dates, Atlas launch copy, specific model IDs, the precise station layout, and API adapter details are not user mandates or proof of the integrated MVP.

Codex generation was tested live. API adapters require keys and separate verification. The frontend now calls the Python ledger API, which uses Elmir’s engine and Danny’s retrieval with Voyage and Atlas Vector Search. Atlas stores workspace snapshots and precedent vectors. Service receipts are returned in request responses, not streamed. The live correction → retrieval → new-resolution path and persistence across backend restart were verified. D44 supersedes the earlier limited-parser-only implementation boundary with bounded, validated model extraction and semantic review; the old parser remains an explicit opt-out.

September 26 replay diagnosis: Atlas Vector Search is called for new structured conflicts; ordinary messages and lookups covered by a saved human answer skip retrieval. The inspector now retains arrival-gated service receipts across the combined review/correction cycle instead of dropping the review’s search when the correction starts. Missing-call explanations use recorded evidence, and replay remains read-only. This fixes the existing completed-cycle requirement without adding retrieval calls.
